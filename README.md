# Salem Star Speaker — frontend

The public website for **Salem Star Speaker — The Speaking Contest**, presented by
Salem Parenting Club in association with Speak Up Salem Toastmasters Club.

A single static page. No backend, no database, no payment integration — see
[Known limitations](#known-limitations).

> Design decisions, research notes and the verified event facts live in
> [`PROJECT-NOTES.md`](./PROJECT-NOTES.md). Read that before changing content.

---

## Quick start

```bash
cd website/sss-web
npm install
npm run dev        # http://localhost:5173
```

## Production build

```bash
npm run build      # writes dist/
npm run preview    # serves dist/ at http://localhost:4173 to check it
```

The build is fully static: HTML, CSS, JS and images. Nothing in `dist/` needs
Node.js at runtime.

## Deploying to cPanel

1. Run `npm run build` locally. Do **not** build on the server — cPanel hosting
   is not assumed to have Node.js.
2. Open **cPanel → File Manager** and go to the document root
   (`public_html/`, or `public_html/<subdomain>/`).
3. Upload the **contents of `dist/`** — not the `dist` folder itself. The result
   should be `public_html/index.html`, `public_html/assets/…`,
   `public_html/images/…`, `public_html/.htaccess`.
   - File Manager hides dotfiles by default. Turn on
     **Settings → Show Hidden Files** so `.htaccess` is uploaded and visible.
   - Uploading a zip and extracting in place is faster than uploading files
     individually.
4. Enable HTTPS: **cPanel → SSL/TLS Status → Run AutoSSL**, then uncomment the
   HTTPS redirect block at the top of `.htaccess`.
5. Load the site and check that fonts, images and the registration form work.
   Hard-refresh once (`Ctrl`/`Cmd` + `Shift` + `R`) — `index.html` is served
   with `no-cache`, but a proxy may still hold an old copy briefly.

### Redeploying

Replace `index.html` and the `assets/` folder. Filenames in `assets/` are
content-hashed, so old files can be deleted safely once the new `index.html` is
in place.

### What `.htaccess` does

- Serves `index.html` for unknown paths instead of a bare 404.
- Compresses text responses.
- Caches hashed assets for a year and `index.html` not at all, so a redeploy is
  picked up immediately.
- Sets `X-Content-Type-Options` and `Referrer-Policy`.
- Blocks direct access to dotfiles.

**The SPA rewrite is now required, not optional.** The app has client-side
routes (`/registration`, `/registration/kid`, `/registration/teen`,
`/registration/adult`) that exist only in JavaScript. Without the rewrite, a
direct link or a refresh on one of those URLs returns a 404 from Apache.

**The build must be served from the document root.** `vite.config.js` now uses
`base: '/'` — with the previous relative base, a direct load of
`/registration/kid` would resolve `./assets/...` against `/registration/` and
404 on every asset. To deploy into a subdirectory instead, set `base` to that
subdirectory and adjust the `.htaccess` rewrite target to match.

## Stack

| | |
| --- | --- |
| Framework | React 19 |
| Build | Vite 8 (`base: './'`, so it runs from any document root) |
| Styling | Tailwind CSS v4 via `@tailwindcss/vite` |
| Motion | GSAP 3 + ScrollTrigger |
| Smooth scroll | Lenis, driven by the GSAP ticker |
| Icons | lucide-react |
| Type | Fraunces + Manrope (Google Fonts, variable) |

`sharp` is a dev dependency used once by `scripts/crop.mjs` to cut the image
assets out of the event poster. It is not part of the bundle.

### Changing event content

Edit [`src/data/event.js`](./src/data/event.js) and nothing else. The fee, date,
venue, deadline, contacts, categories, benefits and FAQs all read from there, so
the fees cannot drift between sections.

Three places outside that file repeat event facts for reasons that cannot be
avoided, and must be updated by hand if the details change:
`index.html` — the `<title>`, meta description, Open Graph tags, JSON-LD block
and the `<noscript>` fallback.

### Regenerating images

```bash
node scripts/crop.mjs
```

Re-cuts `public/images/` from `src/assets/source/poster.jpg`. The organiser logos
are extracted pixel-for-pixel and are never redrawn or restyled.

preselection, every validation rule, the absence of WhatsApp wording and links,

## Known limitations

**Registration is live.** Each category form carries the seven official fields
and full client-side validation, then posts to `sss-api`, which creates a
Razorpay order, verifies the payment signature and confirms the entry. See
section 8 of [`PROJECT-NOTES.md`](./PROJECT-NOTES.md) for the flow and the
exact validation rules.

Gaps worth knowing about: there is no way to recover a registration after the
tab closes (no status-by-reference route), no capacity or sold-out handling
behind the "limited entries" copy, and the registration page cannot reach the
policy pages.

**Fees are per category.** Juniors ₹99, Teens ₹199, Adults ₹299 — set in
`src/data/event.js`. The ₹999 flat fee on the original poster was an
early-development figure and is confirmed incorrect.

**Payment is collected** on the registration pages through Razorpay, against
orders created by `sss-api`. The server sets the amount from its own config; the
client never sends a price.

**No analytics or tracking**, and therefore no cookie banner.

**No venue map.** The organisers have supplied a venue *name* but no verified
address or coordinates, so none is asserted — on the page or in the JSON-LD.

**`og:url` and `og:image` are omitted** from `index.html` until the live domain
is confirmed. Add both before launch, or link previews will be bare.

## When the backend arrives

`sss-api/` and `sss-admin/` are intentionally empty. When they are built:

1. [`src/sections/Registration.jsx`](./src/sections/Registration.jsx) — in
   `handleSubmit`, replace the `setStatus('checked')` branch with a `POST` of
   the seven field values, and replace the "cannot submit them yet" panel with a
   real confirmation shown only after the request succeeds. Add `checking` as a
   genuine in-flight state (the fieldset already disables on it) and handle
   failure. The validation in
   [`src/utils/validation.js`](./src/utils/validation.js) must be re-implemented
   server-side; client validation is a convenience, not a control.
2. **Parental consent.** The contest accepts participants from age 10, so the
   organisers need a parent/guardian consent process in place before real
   registrations are collected. This build does not implement one, and removing
   the old consent checkbox did not satisfy that requirement.
3. [`src/data/event.js`](./src/data/event.js) — fee, deadline and remaining
   places should come from the API rather than the bundle.
4. Payment, receipts and seat availability are out of scope here and are not
   simulated anywhere in this code.
